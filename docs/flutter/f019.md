## 0.Navigator

`Navigator` 维护着一个先进后出（LIFO）的路由历史栈. 常用方法如下：

| 方法名 (含 Named 版本)  | 核心行为 | 典型工程场景 |
| --- | --- | --- |
| `pushReplacement` / `pushReplacementNamed`  | 销毁当前栈顶页面，并在**原位置替换**压入新页面（旧页触发 `dispose`）。 | 登录成功跳转首页、Splash 闪屏页跳转主界面。防止用户返回到登录页/闪屏页。 |
| `pushAndRemoveUntil` / `pushNamedAndRemoveUntil` | 压入新页面，并**根据条件清空**之前的历史路由栈。传入 `(route) => false` 可清空全部历史。 | **退出登录**重置到登录页、**重置应用状态**、开户/实名认证成功后一键重置路由回首页。 |
| `popUntil` | 沿路由栈连续向上 `pop`，直到遇到满足条件（`predicate` 为 `true`）的页面为止。 | 多步骤表单填写完成（步骤 1 → 2 → 3），点击提交后一键返回步骤 1。 |
| `canPop` | 返回 `bool`，判断当前路由栈深度是否大于 1（即当前页是否**可以**被安全弹出）。 | 自定义 `AppBar` 的返回按钮时，用于判断是否渲染返回箭头图标。 |
| `maybePop` | 安全版的 `pop`。若 `canPop` 为 `false` 则什么都不做，防止将根页面弹空导致应用黑屏/退出。 | 响应硬件返回键或自定义手势时的防御性保护机制。 |
| `popAndPushNamed` | 先 `pop` 当前页面，并将前一个页面的返回值抛出，随后压入新页面。 | 侧边栏菜单（Drawer）切换：先关闭 Drawer，再打开选中的新页面。 |
| `removeRoute` / `removeRouteBelow` | 从路由栈中**静默移除**指定 Route（无退场过渡动画，不触发页面层叠重建）。 | 移除中间挂载的静默授权页、广告过渡页，使点击返回时直接跨过该页。 |

## 1.基本路由

代码：
```dart
// Push, 返回值是  static Future<T?>
Navigator.push(BuildContext context, Route<T> route)

// Pop，返回值是 void
Navigator.pop(BuildContext context)
```

---

代码示例：

1. 调起方（页面 A）：发起 `push` 并 `await` 等待结果

```dart
// 1. 指定泛型类型，例如等待返回一个 String
final String? selectedCity = await Navigator.push<String>(
  context,
  // CityPickerPage如果需要参数，直接初始化时传入即可，例如 CityPickerPage(current: "北京")
  MaterialPageRoute(builder: (context) => const CityPickerPage()),
);

// 2. 一定要进行非空安全检查（防止用户直接点了系统返回键）
if (selectedCity != null) {
  print('用户选择的城市是: $selectedCity');
  setState(() {
    _currentCity = selectedCity;
  });
} else {
  print('用户未选择，直接返回了');
}
```

2. 被调起方（页面 B）：关闭页面并回传数据

```dart
class CityPickerPage extends StatelessWidget {

  // 可以在这里定义 final 属性，用来处理 CityPickerPage 初始化时外界传参

  const CityPickerPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('选择城市')),
      body: ElevatedButton(
        child: const Text('选择 北京'),
        onPressed: () {
          // 在 pop 的第二个参数中传入要回传的数据
          Navigator.pop(context, '北京');
        },
      ),
    );
  }
}
```


## 2.命名路由

### 2.1 配置路由

在 `MaterialApp` 中注册路由映射表（`initialRoute` 与 `routes`）:
```dart
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Named Routes Demo',
      // 1. 设置应用启动时加载的初始路由（替代 home 参数）
      initialRoute: '/',
      // 2. 集中注册路由表
      routes: {
        '/': (context) => const HomeScreen(),
        '/detail': (context) => const DetailScreen(),
        '/picker': (context) => const DataPickerScreen(),
      },
      // 3. 全局 404 兜底处理
      onUnknownRoute: (settings) => MaterialPageRoute(
        builder: (context) => const NotFoundScreen(),
      ),
    );
  }
}
```

> 注意：使用 `initialRoute` 时，不可同时设置 `home` 属性，否则会触发路由冲突异常。

### 2.2 跳转push

**发起跳转（带参数）**

在调用 `Navigator.pushNamed` 时，通过 `arguments` 参数传递任意类型的 `Dart` 对象：
```dart
// 在 HomeScreen 中发起跳转
void _navigateToDetail(BuildContext context) {
  Navigator.pushNamed(
    context,
    '/detail',
    arguments: {'id': 10086, 'title': '订单详情'}, // 支持传递 Map、Custom Model 等
  );
}
```

### 2.3 返回Pop

**被打开页面提取参数** 在目标页面的 `build` 方法中，通过 `ModalRoute.of(context)` 获取参数：

```dart
class DetailScreen extends StatelessWidget {
  const DetailScreen({super.key});

  // ⚠️这种方式，在 init 方法中，使用 ModalRoute.of(context)?.settings.arguments 获取参数是失败的
  // 因为 Flutter 将路由跳转，设计为了异步 Future 数据流

  @override
  Widget build(BuildContext context) {
    // 提取路由传递的 arguments（需注意强转与空安全）
    final args = ModalRoute.of(context)?.settings.arguments as Map<String, dynamic>?;

    final int id = args?['id'] ?? 0;
    final String title = args?['title'] ?? '未知';

    return Scaffold(
      appBar: AppBar(title: Text(title)),
      body: Center(child: Text('Item ID: $id')),
    );
  }
}
```


命名路由同样支持泛型**返回值传递**，`Navigator.pushNamed` 会返回 `Future<T?>`：

```dart
// 1. 调起方：指定期待的返回类型 <String> 并 await
Future<void> _pickData(BuildContext context) async {
  final String? result = await Navigator.pushNamed<String>(context, '/picker');

  if (result != null) {
    print('接收到返回值: $result');
  }
}

// 2. 被调起方 (DataPickerScreen)：关闭页面并抛出数据
ElevatedButton(
  onPressed: () {
    Navigator.pop(context, '选中的结果数据');  // 增加数据参数
  },
  child: const Text('确认选择'),
);
```

### 2.4 优化-动态路由

**使用 `onGenerateRoute` 优化构造函数注入**

直接在 `routes` 表中注册会导致一个**架构痛点**：目标 `Widget` 必须在自己的 `build` 方法内部去提取 `ModalRoute.of(context)`，导致 `Widget` 无法直接通过构造函数（Constructor）声明 `required` 属性，打破了不可变（Immutable）控制链。

生产环境中，更推荐结合 **`onGenerateRoute`** 实现干净的**构造函数注入**：

```dart
MaterialApp(
  initialRoute: '/',
  // routes: {...} 如果也写了 routes，则会先去 routes 判断，没有则再进入 onGenerateRoute 里
  // 不使用静态 routes 映射表，使用动态解析
  onGenerateRoute: (RouteSettings settings) {
    switch (settings.name) {
      case '/':
        return MaterialPageRoute(builder: (_) => const HomeScreen());

      case '/detail':
        // 在路由统一拦截点进行参数校验与解析
        final args = settings.arguments as Map<String, dynamic>;
        return MaterialPageRoute(
          builder: (_) => DetailScreen(
            id: args['id'] as int,
            title: args['title'] as String,
          ),
        );

      default:
        return null; // 返回 null 会自动触发 onUnknownRoute
    }
  },
);

// 此时 DetailScreen 可以写出非常干净的构造函数
class DetailScreen extends StatelessWidget {
  final int id;
  final String title;

  const DetailScreen({
    super.key,
    required this.id,
    required this.title,
  });

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(title)),
      body: Center(child: Text('ID: $id')),
    );
  }
}

```
