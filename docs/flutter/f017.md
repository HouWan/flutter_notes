## 1.Pub

### 1.1 Pub概览

**Pub** 是 `Dart` 和 `Flutter` 官方的包管理平台（托管于 [pub.dev](https://pub.dev/)）。

和 iOS、Android 的对比如下：

| 维度 | Flutter (Pub) | iOS (CocoaPods / SPM) | Android (Gradle / Maven) |
| --- | --- | --- | --- |
| **配置文件** | `pubspec.yaml` | `Podfile` / `Package.swift` | `build.gradle.kts` |
| **版本锁定文件** | `pubspec.lock` | `Podfile.lock` / `Package.resolved` | `gradle.lockfile` |
| **命令行工具** | `flutter pub` / `dart pub` | `pod` / `swift package` | `./gradlew` |
| **全局缓存目录** | `~/.pub-cache` | `~/Library/Caches/CocoaPods` | `~/.gradle/caches` |

---

例如执行 `flutter pub add dio` 时，Flutter 引擎会自动完成三件事：

  - 1. 向 `pub.dev` 发起请求，自动匹配与当前 Dart/Flutter SDK 兼容的最新 `dio` 版本。
  - 2. 将依赖项追加写入项目根目录的 **`pubspec.yaml`** 文件中：
  ```yaml
  dependencies:
    dio: ^5.8.0 # 自动追加

  ```

  - 3. 触发执行 **`flutter pub get`**：下载 Package 源码到全局缓存目录 `~/.pub-cache`，更新锁定文件 **`pubspec.lock`**，并更新原生工程的链接。


### 1.2 `flutter pub`命令

**一、 指定版本号的语法与规则**

指定版本时，包名与版本约束之间使用 **`:`** 分隔。在终端执行时，**强烈建议加上双引号**，防止终端（如 zsh/bash）将 `^`、`<`、`>` 等符号误判为 Shell 特殊字符或重定向指令。

| 语法规则 | 命令示例 | 写入 `pubspec.yaml` 的结果 | 说明 |
| --- | --- | --- | --- |
| **Caret 范围 (推荐)** | `flutter pub add "dio:^5.8.0"` | `dio: ^5.8.0` | 允许升级到不破坏兼容性的最新版（即 `>=5.8.0 <6.0.0`）。 |
| **精确锁定** | `flutter pub add "dio:5.8.0"` | `dio: 5.8.0` | 严格指定该版本，不自动升级。 |
| **版本区间** | `flutter pub add "dio:>=5.0.0 <6.0.0"` | `dio: '>=5.0.0 <6.0.0'` | 显式限制版本范围。 |
| **不写版本** | `flutter pub add dio` | `dio: ^5.8.0` *(假设当前最高为 5.8.0)* | 自动获取 `pub.dev` 上与当前 Dart/Flutter SDK 兼容的最新稳定版。 |

> **提示**：也可以一次性添加多个依赖，例如：
> `flutter pub add dio http "path:^1.9.0"`

> **⚠️撤销添加⚠️**：如果加错了包，无需手动去 `pubspec.yaml` 删除，直接运行 `flutter pub remove dio` 即可完成移除并自动清理缓存链接。

---

**二、 常用命令行参数 (Flags & Options)**

除了添加公有库依赖，`flutter pub add` 还支持以下关键参数：

**1. 添加开发依赖 (`--dev` 或 `-d`)**
将依赖写入 `dev_dependencies`（仅在开发、构建、测试时使用，不打包进最终产物）：

```bash
flutter pub add build_runner json_annotation --dev
```


**2. 本地路径依赖 (`--path`)**
用于大型项目的组件化拆分，直接引用本地 Package：

```bash
flutter pub add my_core_module --path=../modules/my_core_module

```

**3. 强制覆盖依赖 (`--override`)**
直接将依赖写入 `dependency_overrides`（常用于临时排查第三方库之间的版本冲突）：

```bash
flutter pub add "dio:5.0.0" --override

```

**4. 预演与校验 (`--dry-run` 或 `-n`)**
仅在控制台打印 `pubspec.yaml` 会发生什么改变，**不实际修改文件**：

```bash
flutter pub add dio --dry-run

```


## 2.版本控制

### 2.1 版本号约束语法（Semantic Versioning）

* `dio: ^5.8.0`（**Care-about 符号**，常用）：允许升级到不改变大版本号的最新版（即 `>= 5.8.0 < 6.0.0`）。
* `dio: 5.8.0`（**精确锁定**）：严格使用该版本，适合需要高稳定的企业级项目。
* `dio: any`（**危险**）：允许任意版本，易引发 breaking changes。

### 2.2 本地包与 Git 源码依赖（模块化架构）

在 iOS/Android 中常使用 Local Pod 或 Gradle Subproject 进行业务模块化，Flutter 中通过 `pubspec.yaml` 完美支持：

```yaml
dependencies:
  # 1. 本地相对路径依赖 (用于大型项目拆分内部 package)
  my_core_network:
    path: ../modules/my_core_network

  # 2. Git 源码依赖 (用于使用团队私有库或未发布到 pub.dev 的 Fork 分支)
  flutter_custom_sdk:
    git:
      url: git@github.com:your_org/flutter_custom_sdk.git
      ref: main # 支持分支、Tag 或 Commit Hash

```

### 2.3 强制解耦依赖冲突（`dependency_overrides`）

当 A 插件依赖 `foo: 1.0.0`，而 B 插件依赖 `foo: 2.0.0` 导致 `pub get` 报版本冲突（Dependency Version Conflict）时，可在 `pubspec.yaml` 根层级使用覆盖强制统一：

```yaml
dependency_overrides:
  foo: 2.0.0 # 强制全项目使用 2.0.0 版本

```

### 2.4 iOS 原生缓存未更新

* **现象**：更新了插件的 iOS 原生代码或 Pod 依赖后，运行 Xcode 依然报错或未生效。
* **工程解法**：执行 Flutter 清理三板斧：
```bash
flutter clean
cd ios && rm -rf Pods Podfile.lock
flutter pub get
pod install

```


## 3.Plugin/Dart

在 Flutter 生态中，Package 严格划分为两类，其运行机制截然不同：

```
                              ┌── 纯 Dart 包 (如 dio, json_annotation)
                              │    └─ 纯 Dart 逻辑，无原生代码，跨平台无缝运行
第三方库 (Package / Plugin) ──┤
                              └── 原生插件 (Plugin, 如 camera, path_provider)
                                   └─ Dart API + iOS (Swift/ObjC) + Android (Kotlin/Java)

```

当添加了一个包含 iOS/Android 原生代码的 `Plugin` 时，`flutter pub get` 会触发 `Auto-Linking`：

  * **iOS 端**：Flutter 会读取插件中的 `ios/` 目录和 `*.podspec`，自动将依赖注入到项目的 `ios/Podfile` 生成的隐藏配置文件（`.flutter-plugins-dependencies`）中。随后编译时自动触发 `pod install`，将插件作为 Pod 编译进 iOS `Runner.xcworkspace`。
  * **Android 端**：自动将插件的 `android/` 目录作为子模块 `include` 进入 `android/settings.gradle`，并通过 Gradle 依赖编译。
